# 墨水屏 UI 规范 · v1.2

- 状态：**正式冻结，用户已确认**
- 冻结日期：2026-09-02
- 公开样例：`public-v1.2`，保留已确认排版，仅替换为虚构数据。原始开发历史不随公开仓库分发。
- 适用范围：`editable-dashboard.html`、原生位图渲染及墨水屏输出

本文件是唯一有效的 UI 设计基准。用户已确认当前界面；后续开发默认保持外观不变。v1.0/v1.1 为设计过程版本，v1.2 是本次正式冻结版本，不能使用旧截图或旧参数覆盖它。

## 1. 冻结基线

- [原生标准样例](ui-baseline/public-v1.2/native.png)：400×300、严格三色，供视觉回归。
- [基线清单与校验值](ui-baseline/public-v1.2/manifest.json)。
- [验收及变更规则](ui-baseline/public-v1.2/README.md)。

基线中的邮箱、61% 和示例任务用于验证外观，不是冻结真实数据。账号、订阅、额度、时间和任务内容仍正常更新。冻结不等于停用编辑工具或停止自动同步。

## 2. 信息层级与内容

1. 顶部：账号邮箱、订阅类型、日期；不恢复 GPT HUB/ONLINE 或订阅到期日期。
2. 核心额度：左侧大数值表示剩余，右侧表示已使用及下次重置时间。
3. 用量：左侧“30 天用量”，右侧“最后更新”，下方为柱状趋势图；不恢复 USD/TOKEN 和四组金额/Token 指标。
4. 任务：最多三条；主标题是项目名，副标题是对话任务名，右侧是状态；不增加表头、序号、运行时长或进度列。

真实任务不足三条时保留空白，不用示例任务补位。订阅 `pro → Pro 20x` 是当前产品的显示映射，不是接口返回的倍率字段；UI 冻结不增加或改变账户授权。

## 3. 画布、边距与坐标口径

| 项目 | 固定值 |
|---|---|
| 设备画布 | 400 × 300 px |
| 主内容横向范围 | x=10 到 x<390，宽 380 px |
| 左右边距 | 10 px；账号起点额外向内 4 px，即 x=14 |
| 页眉文字绘制起点 | y=8（已确认的顶部例外，不强行改成 10） |
| 普通文案行盒 | 高 16 px |
| 小间距 / 组间距 | 4 px / 8 px |
| 任务组节奏 | 40 px |
| 末行行盒底部留白 | 12 px，文字行盒结束于 y=288 |
| 坐标网格 | 纵向主要起点为 4 px 网格，设备最终坐标全部为整数 |

所有范围使用半开区间 `[上沿, 下沿)`。例如 y=108–116 表示高 8 px。1 px 分割线位于 y=168 时，实际占据 y=168–169。

**间距以行盒/容器计算，不以字形墨迹计算。** 字号不等于字形高度；不同文字的实际墨迹边缘可以不同。原生 y 表示绘制起点，HTML y 表示对应行盒起点；不要因为浏览器字形测量不同而二次缩放设备帧。

## 6. 字体与原生文字渲染

- 字体：项目内置 `assets/fonts/SourceHanSansCN-Bold.otf`，Source Han Sans CN Bold。
- 字重：所有文字统一 700；不得回退到 PingFang 400/500/600，或用描边模拟加粗。
- 正式字号：48 / 18 / 16 / 14 / 12 px，以第 5 节的角色映射为准。
- 字体许可证：[SIL OFL 1.1](../assets/fonts/LICENSE-SourceHanSans.txt)。
- 最终 400×300 画布直接渲染；FreeType 原尺寸灰阶 glyph 栅格化，再执行一次 threshold=144 二值化。
- 不做 embolden、模糊、文字 dithering、二值图膨胀或描边。
- 保持现有 FreeType hinting 路径；不得通过缩小高分辨率图“改善”文字。
- 图像输出只能保留黑/白文字；1-bit 像素台阶是设备限制，不能以灰色或透明度换取抗锯齿。

HTML 使用同一字体文件、700 字重和固定字号。浏览器的字体抗锯齿及字宽测量不是设备输出源，不要求浏览器截图与原生图逐像素相同。

## 7. 额度条与趋势图

### 额度条

- 50 格，仅一行，高 8 px，无单格边框和圆角。
- 总宽 380 px，49 个 1 px 间隔；331 px 分配给单格，单格宽 6 或 7 px，首格从 x=10 开始、末格结束于 x=390，尾部不得额外留空白。
- 剩余区：纯黑实心。
- 已使用区：固定 1×1 px 黑白棋盘点阵，相邻行错位；原生条件为 `(row + column + index) % 2 == 0` 的点填黑。
- 每格约代表 2%，格数是近似图示，主百分比是精确读数。不得把已使用区改回真灰色或空心框。
- 当前浏览器与 Python 的半格舍入方式不同，奇数百分比时可能相差一格；该数据映射差异不属于本次外观冻结修改，后续应单独验证，不靠更改布局掩盖。

### 趋势图

- 380×16 px，底边 y=164；46 个横向槽位按当前实现分配。
- 柱宽 2–4 px；非零柱最小 4 px、最大 16 px；零值占位高 1 px。
- 高度按当前序列峰值归一化。不得把柱状图误读为任务进度或订阅账单。
- 当前红色强调柱沿用既有实现；本次不更改用量数据口径、采样窗口或高亮逻辑。

## 8. 颜色、线条与状态

| Token | 色值 | 用途 |
|---|---|---|
| WHITE | `#FFFFFF` | 背景、反白文字 |
| BLACK | `#000000` | 文字、剩余额度、趋势柱、分割线 |
| THIRD / ALERT | `#C62828` | 等待指令、失败状态、强调柱 |

第三色锁定的是逻辑像素值和设备红色位平面，不是对屏幕红墨水的色度测量承诺。

| 状态 | 背景 | 文字 | 边框 |
|---|---|---|---|
| 运行中 | 黑 | 白 | 黑色 1 px |
| 等待指令 | 红 | 白 | 红色 1 px |
| 排队中 | 白 | 黑 | 黑色 2 px |
| 失败（有对应数据时） | 红 | 白 | 红色 1 px |

- 状态标签统一 72×24 px、圆角 2 px，文字居中。
- 描边仅允许 1/2 px；圆角仅允许 0/2/4 px，当前标签使用 2 px。
- 页眉为 1 px 黑色实线；任务分割为 1 px 虚线，原生使用 2 px 实 / 2 px 空。
- 不增加各区域外框，不恢复逐格描边。
- 禁止真灰色、透明度、阴影、渐变、装饰性图标及缩放后抗锯齿设备图。

## 9. 动态内容与边界

- 项目名、对话名保持单行；宽度超出 292 px 时省略，不能换行挤压任务行高。
- 账号原生最多使用 200 px 文本宽度，超出省略；订阅放在账号之后。
- 不把快照的百分比、邮箱、日期、三个示例任务写成永久真实值。
- 不将“下次额度重置”改写为“订阅到期”。
- 顶部日期和最后更新时间沿用现有快照来源；数据接口、生命周期映射、刷新频率、BLE 协议仍由对应实现和协议文档负责。
- 编辑工具栏只属于桌面操作区，不进入设备画布，不改变导出帧尺寸。

## 10. 验收与回归

每次明确获准修改 UI 后，至少检查：

1. 更新本规范、版本和变更记录，再同步 HTML 与原生渲染器。
2. 同一示例数据在最终 400×300 下比较；冻结图不允许被静默覆盖。
3. 检查页眉 y=8、任务起点 176/216/256、16 px 普通行高、40 px 组节奏和最后 12 px 行盒留白。
4. 检查字号/700 字重、50 格点阵、三色集合以及无文本/分割线碰撞。
5. 检查长项目名/副标题省略、少于三条任务留白、无半像素纵向位置。
6. 运行现有 HTML、文字渲染、状态同步及 Swift 协议测试。
7. 如涉及设备输出，单独记录 BLE 下发结果与用户实屏观感；不能用 PNG 或 129/129 包成功替代实屏视觉确认。

```bash
python3 -m unittest discover -s Tests/HtmlLayoutTests -v
python3 -m unittest discover -s Tests/TextRendererTests -v
python3 -m unittest discover -s Tests/StatusSyncTests -v
swift build -c release
swift run eink-core-tests
```

## 11. 变更控制与旧稿处理

- 后续状态同步、BLE、稳定性和数据源任务默认不得修改字体、坐标、间距、颜色或组件结构。
- 只有用户明确要求 UI 改动时才解除对应部分的冻结；不得擅自“优化”为另一版。
- `design-qa.md` 的早期 Pass、`output/layout-measurements/` 的旧坐标及各种字体对比图均为历史材料，不是当前规范。
- `output/eink-dashboard-400x300.png` 是可更新的实时画面，不作为不可变基线。
- 冻结图、基线哈希或渲染规则变化时，应新增版本，不覆盖 v1.2 的基线。
- 本次只冻结已确认外观和记录已知边界，不修改接口、状态模型、权限或自动刷新行为。
