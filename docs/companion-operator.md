# Codex Ink · 开发版操作与切换边界

本开发版把管理界面放在 Mac 菜单栏，不改变设备 UI v1.2。构建、预览、绑定和实际启用是不同步骤；只看到窗口不表示旧服务已被接管。

## 构建和打开

在项目根目录执行：

```bash
python3 tools/build_companion.py
```

构建器输出唯一目录中的 `Codex Ink.app`，包含脚本、字体和许可，采用 ad-hoc 开发签名；不会启动、安装、改 hooks 或打开登录启动。Python/Pillow 仍依赖本机已验证环境，暂不是面向其他 Mac 的正式安装包。

### 名称与旧安装兼容

产品名、窗口标题和系统登录项统一为 **Codex Ink**。内部 Bundle ID `com.ben.codex-eink.companion.dev`、`eink-companion` 可执行文件和 `CodexEInk` 数据目录保持不变。

若已信任的 hooks 指向旧 `EInkCompanion.app/Contents/Resources/runtime/`，改名时保留该目录的真实文件与原始内容，只更新可见 App；不要删除该目录、改写信任记录或用符号链接替代。旧目录仅作为兼容 runtime，不保留可启动的旧应用副本。后续完整迁移应使用既有接管/恢复流程。登录启动保留原先启用状态。

打开应用后，首次配置窗口会显示；后续也可以从菜单栏“设置…”打开。默认只预览，不自动向屏幕发送。临时目录应用可用于检查和预览；实际安装 hooks 前需要把应用放在稳定位置，不能让 hooks 指向可能被清理的系统临时目录。

## 配置顺序

1. **检查运行环境**：确认 Codex、Python 的实际路径，点击生成预览。校验失败保留最后有效画面，不把未知额度填成 100%。
2. **授权和绑定**：点击扫描，亲自处理系统授权；选择设备，GATT 验证和断开确认完成后保存设备标识。名称只用于显示，不能凭同名自动换设备。
3. **检查接管状态**：检查现有 hooks、启动项与进程。存在旧调用方、未知来源或未完成信任时不能启用发送。
4. **安装 / 接管**：只在准备好后点击并确认；退出 Codex 会中断当前工作，应由用户择机操作，不由本应用强制执行。
5. **回到 Codex 信任新 hooks**：不提供“已信任”复选框绕过。安装回执必须来自新入口实际收到的有效事件。
6. **启用同步**：仅在数据、设备绑定和接管检查通过时可用；首次实际发送需要单独观察屏幕效果。

登录启动默认关闭，可按需开启；系统显示待授权或被关闭时，如实展示，不自动重新注册。

### 普通启动与登录后恢复配置

开启“登录时打开”前先保存有效配置。应用将当前配置目录记录到 `~/Library/Application Support/CodexEInk/startup.json`，再登记系统登录项。之后 Finder 打开或登录启动都会读取同一目录，保留设备绑定、同步启用及暂停状态，无需附加 `--state-dir`。

已有版本若曾用 `--state-dir` 启动，更新后先沿用该参数打开一次，关闭再开启“登录时打开”，即可保存当前目录。关闭登录启动只停用系统登记，不删除这份目录选择。

显式 `--state-dir` 优先于启动记录，且不会仅因测试启动就覆盖记录；没有启动记录时仍使用原默认 `companion/`。`--runtime-root` 是开发参数，登录启动使用当前应用包内 runtime。

启动记录或其目标配置损坏、丢失时，应用显示错误并停止自动恢复，不搜索其他目录、不生成替代配置，也不覆盖原文件。修复所提示的文件后重新打开应用。目录选择与 hooks 信任是独立条件，读取到设置不能跳过原有接管检查。

### 退出 Codex 后仍看到旧服务

系统登记的旧 `--no-push` 轮询服务不会随 Codex 退出，正常显示“旧方案仍在运行”，应由“安装 / 接管…”停用，不需要手动杀进程。程序按系统登记 PID、实际 Python 类型和完整脚本参数识别它，支持 macOS Python 启动器与运行时路径不同的情况。

`sender_running` 仍可表示旧 hook/实际刷屏尚未结束，或进程身份不匹配；它不是“可忽略”开关。保持伴侣窗口打开，退出 Codex，待当前发送结束后点击“安装 / 接管…”并确认。成功后再打开 Codex 审阅新 hooks；单纯退出并立刻重开不会完成接管。

## 运行状态

- **待配置 / 需要处理**：先解决路径、数据、蓝牙或接管检查，不能绕过发送门槛。
- **就绪**：设备已绑定，空闲时可以断开；不代表一直保持蓝牙连接。
- **同步中**：一帧在途，不并发发送；先完成或清理旧请求，才处理新请求。
- **已暂停**：新任务事件仍可保存，但不发送。正在发送时点击暂停，会等待当前帧结束。
- **等待恢复**：请求未丢弃，按退避策略等待；永久错误需用户明确重试或真实系统状态恢复。

“数据读取”和“成功下发”分开显示。前者不是设备刷新时间；后者也不是用户已经确认屏幕观感。

## 数据含义

- 每周额度必须匹配 Codex 的 10080 分钟窗口，不能把其他模型、5 小时额度或缺失值混入。
- 套餐使用服务确认的类型；`pro` 显示为 `Pro`，不再在新入口凭空推断 `20x`。
- 趋势取最近 30 个自然日，一天一柱；按周一至周日分组，仅自然周边界增加间距。确认的空历史是零活动，未知历史则阻止新帧。
- 原 HTML 示例和旧同步入口保持兼容，它们不因此自动升级为新数据口径。
- 数据源未提供对话名称时，新入口显示“未命名任务”，不把提示词预览当作任务名称展示到桌面屏幕。

## 接管和恢复

安装助手只变更本应用已识别的条目，保留其他 hooks。配置被同时修改、来源无法核验、程序仍运行或备份不一致时停止操作并报告原因，不整体覆盖用户文件。

文件发布使用可恢复事务与不可覆盖的重命名，不把普通文件替换称为原子 CAS。旧调用方停止后，原文件会短暂移至同目录保留版本；任何冲突都保留文件并停止。若迁移中断，先通过恢复流程处理未完成事务，再启动 Codex；不要手动删除隐藏的保留版本或事务记录。

临时目录、未知 hooks 来源、用户未信任及旧发送者仍活动都不是可勾选忽略的警告。需要先修复或扩展明确的支持范围，不能通过清空用户配置或关闭安全校验来强行启用。

恢复旧配置前必须先停止伴侣发送。恢复同样保留安装后新增的无关 hooks；若本应用条目已被用户改动，报告冲突，不盲目回滚。不会删除旧运行时备份，也不会自动让新旧两个发送者同时运行。

## 验收清单

- 构建及单元测试不能代替真实绑定、发送和断开验证。
- 实际迁移需用户配合退出/重新打开 Codex、审阅新 hooks，并触发真实任务事件。
- 登录启动、至少三次休眠唤醒及 24 小时运行记录分别记录，未完成时只能标为开发版可试用。
- 第二台 Mac、Intel 构建、独立运行环境、Developer ID/公证和 DMG 属于后续分发阶段。

## v0.4.0 菜单与刷新策略

菜单栏只保留原图标，同步中显示蓝点，需要处理时显示红点，其余状态无提示点。完整状态保留在菜单和辅助功能名称；错误显示短摘要，详情在设置页。已暂停时只显示一个继续同步；未启用同步时隐藏暂停项，正在暂停时禁用相关操作。

后台约每 5 秒检查任务；普通请求合并 30 秒，距上次成功发送至少 180 秒，定时取数间隔 600 秒。业务摘要排除读取/事件时间，再用像素去重；摘要缓存仅在当前 worker 内有效。普通启动、继续和后台恢复不强制刷新。手动刷新和显式错误重试保留强制语义，但不能绕过配置、暂停或永久错误门禁。

构建输出带更新脚本，固定 runtime 保留 Hooks，sync-runtime 更新同步代码。更新器允许最多 90 秒启动恢复，仍要求新 ready 检查；持续失败回退。该恢复处理不代表所有系统层检查超时已根治。参见双语安装指南。

## v0.4.1 每天一柱

30 天用量改为连续 30 个每日柱，周一至周日为一组，周日与周一间额外留白；跨月不重置，首尾允许不完整周。真实零用量保留位置。数据仍为每日 tokens，不宣称等同后台套餐用量。其他字体、布局和刷新策略不变。
